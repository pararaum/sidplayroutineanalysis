# CLAUDE.md

`ntedit` is a Tkinter editor for NinjaTracker V2 style C64 music with real-time
playback and PSID export. Background and format details: `docs/ANALYSIS.md`
(read it before changing packing or player code). User docs: `README.md`.

## Layout

- `ntedit/model.py` - song model (Row, Pattern, Command, Track, Subtune, Song).
  Values are in *editor* representation; 1-based table positions, pattern and
  command numbers like the original editor.
- `ntedit/packed.py` - `pack(song, base)` / `unpack(data, base)` for the packed
  "gamemusic" block, plus editor<->play-routine value conversions.
- `ntedit/psid.py` - builds the memory image (player.bin + packed data at
  `nt_end`) and PSID v2. Reads symbol addresses from `player.lbl`.
- `ntedit/emu.py` - py65 runs the real play routine; pyresidfp renders it.
- `ntedit/audio.py` - sounddevice streaming thread (`LivePlayer`).
- `ntedit/project.py` - JSON projects, import of `.bin` and own `.sid` files.
- `ntedit/gui.py` - `Grid` canvas widget plus Song/Pattern/Command/Table editors, `App`.
- `player/` - ca65 port of `nt2play.s` (`sidwrap.s` wraps it, `sid.cfg`, `Makefile`).
  `ntedit/player.bin` and `player.lbl` are generated by it and committed.
- `tests/` - pytest suite; `gui_smoke*.py` are manual headless GUI checks.

## Commands

    python3 -m venv --system-site-packages .venv   # tkinter comes from the system (python3-tk)
    .venv/bin/pip install numpy py65 pyresidfp sounddevice pytest
    .venv/bin/python -m pytest tests                # whole suite, ~2 s
    make -C player                                  # rebuild player.bin/player.lbl (needs cc65)
    .venv/bin/python -m ntedit [file]               # run the editor
    PYTHONPATH=. xvfb-run -a .venv/bin/python tests/gui_smoke.py out.png   # headless GUI + screenshot (needs xvfb, imagemagick)

System packages used in this environment: cc65, python3-tk, python3-venv, xvfb,
imagemagick, libportaudio2, dasm and sidplayfp (the last two only for
cross-checking against the original player and rendering SIDs).

## Invariants and gotchas

- **Byte-exact round trip**: `pack(unpack(x)) == x` for `tests/data/gamemusic.bin`.
  Keep it. Row encodings are chosen to match the original editor (`$0A` key-off,
  `$06` key-on/empty, `$04`/`$08` gate+command, `$01` command-only).
- **Register-stream golden test** (`tests/test_emu.py`): the cc65 player must emit
  the same SID writes as the original dasm player. If you touch `player/nt2play.s`,
  this must still pass.
- Packed data contains **absolute addresses**; always `pack`/`unpack` with the
  address the data will live at (`psid.DATA_ADDR` for exports, `$1000` for the
  original example).
- The player patches its own code (`nt_newmusic`), so the SID `init` must call it
  every time (the wrapper does).
- Table positions in command pointers and jump targets are 1-based; 0 = none/stop.
- A track must not end with a transpose; empty voices are auto-filled with a
  silent pattern at export (`packed._prepare`).
- `psid.LOAD_ADDR` is `$1000`, header load address field is 0 and the image is
  preceded by its 2-byte load address.
- `Grid` subclasses must call `app.push_undo()` before mutating the song.
- Canvas widgets created before their packing container need `tk.Misc.lift`
  (see `App._boxed`), otherwise they are hidden.

## Status / open items

Done: model, packer, PSID export, emulation, live playback, GUI editors, tests.
Not done: copy/paste, SFX support, note preview while typing, storing command
names in exported SIDs, editor-style display of the transpose byte (the
original readme's "$C0 = zero" disagrees with the player; player semantics
are used). Live audio output has not been tried on real hardware (the
development container has no sound device); offline WAV export works.
